## ① 手机互联令牌走 DPAPI

| 项 | 做法 |
|---|---|
| 令牌 | 生成方式不变：32 字节随机数，base64url 编码，无填充，43 个字符 |
| 落盘 | `%APPDATA%\OpenMinis\remote-mcp-token.dpapi`，内容为 `{"version":1,"scheme":"dpapi","blob":"<Base64>"}`；作用域和 entropy 与 P3-1 相同（都用 `SecretProtector`） |
| 迁移 | 应用启动时执行，手机互联关着也会迁。旧明文 `remote-mcp-token` 加密后**令牌值不变**（已配对的手机不用重新添加），旧文件先覆写再删除；如果上次迁移中断留下了明文，下次读取时清掉 |
| 无法解密（换了账户或电脑） | 生成新令牌，旧文件另存为 `.unreadable-<时间戳>`，设置 › 手机互联用红字提示需要在手机上重新添加；轮换令牌后提示消失 |
| 加密失败 | 有旧明文时，旧文件原样保留，继续使用并给出提示；没有旧明文时，新令牌只保存在内存里。**任何情况下都不写明文** |
| 非 Windows | 照旧使用明文文件，方便 CI 和开发 |

## ② DWM 圆角与投影

- `platform/DwmPolicy.kt`：纯逻辑部分，有单测。`platform/WindowsDwm.kt`：JNA 调用 `dwmapi` 和 `user32`，没有新增依赖
- **投影**：DWM 只给带边框样式的窗口画投影，所以给窗口加上 `WS_THICKFRAME | WS_CAPTION` 这类样式位，再子类化窗口过程，在 `WM_NCCALCSIZE` 里让客户区等于整个窗口。这样 AWT 的 insets 仍是 0，第一批的布局和缩放都不变。另外把 frame 向客户区延伸 1px
- **圆角**：`DWMWA_WINDOW_CORNER_PREFERENCE`，浮动时为 ROUND，**最大化时为 DONOTROUND**，同时关掉投影边距；还原后两者恢复
- DWM 接管边框后，不再画第一批的 1px 描边（DWM 会把方形描边裁成断角，Win11 也会自己画边框）。Win10 不认这个圆角属性：保持方角和 1px 描边，投影照样有
- 最大化仍由应用自己做：系统发来的 `SC_MAXIMIZE`，以及 Win+↑ 触发的 OS 最大化，都转成应用自己的「最大化到工作区」，不会盖住任务栏，`window.json` 的逻辑也不变；从任务栏还原最小化的窗口照常交给系统处理
- 屏蔽 `SC_KEYMENU`：加上边框样式后系统菜单会回来，屏蔽后 Alt+Space 不会和应用自己画的菜单同时弹出
- 设置窗口和计划任务窗口走同一条 `AttachChrome` 路径，也有圆角和投影（没有最大化和最小化）
- 所有原生调用失败时只记日志，退回第一批的外观；`-Dopenminis.dwm=false` 可整体关闭，用户侧的退路仍是「沉浸式窗口」开关
- 附带的可能收益：加上 `WS_MINIMIZEBOX | WS_SYSMENU` 后，「点任务栏图标最小化」这条第一批的已知限制**可能**会消失，需要真机确认

## 真机重点核对

1. Win11 上主窗口和两个对话框都有圆角和投影，四角没有断开的描边
2. 最大化后变成直角、没有投影、不盖任务栏；还原后圆角和投影都回来
3. Win+↑ 最大化的结果和点按钮相同；Alt+Space 只弹出应用自己的菜单
4. 窗口最上沿没有白条，也没有 1px 的玻璃线；失焦时没有画出系统标题栏
5. 拖动和 8 向缩放的手感与第一批一样
6. 点任务栏图标能否最小化
7. 令牌迁移后：`remote-mcp-token` 已删除，只剩 `.dpapi` 文件；手机不用重新添加就能继续调用
