## 检查顺序（与 MCP-SERVER.md 一致）

1. 网络层：路径不对 → 404；来源 IP 非私有，或 Origin 不在允许列表 → 403；请求体超过 1 MB → 413
2. 锁定 → 429 + Retry-After
3. Bearer 鉴权（initialize 也要带）→ 401，响应体不含 `session`
4. HTTP 动词与头：动词不对 → 405（带 `Allow: POST, DELETE`）；版本头不符 → 400；Accept 不符 → 406；Content-Type 不符 → 415
5. 先解析请求体（批量请求或解析失败 → 400），再查会话：缺会话头 → 400，会话不存在 → 404。这两种响应体是固定的，都含 `session`
6. JSON-RPC 方法分发

## 补充的三个设计点

1. **initialize 遇到会话头**：会话仍有效时，返回 JSON-RPC 错误「already initialized」，不发新的会话 ID。会话头未知或已过期时，忽略这个头并新建会话，正好对应手机收到 404 后重新 initialize。
2. **错误文本不回显客户端输入**：「method not found」和「unknown tool」都不带方法名或工具名，否则客户端输入里一旦含有 `session` 字样，就会触发无限重连。
3. **日志最小化**：只记 IP、动词、去掉查询串的路径和状态码，从不记录请求头和请求体；异常只记录类名。测试会扫描日志和标准错误输出，确认里面既没有令牌，也没有 `Authorization`。

## 已知取舍

- 锁定按 IP 计算。同网段的人用错误令牌连打 5 次，就能把合法手机锁在外面 60 秒（已写进 MCP-SERVER.md）。
- Hyper-V、WSL、Docker 的虚拟网卡如果是私有地址，也会被监听。它们只在本机内部可达，状态区会写明网卡名。
- 令牌文件在第一次需要时生成：第一次鉴权，或打开「手机互联」设置页时。
