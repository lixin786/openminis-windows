## 为什么断开要带 10 分钟拒绝

如果只删掉会话，手机下一次请求会收到 404 “session not found”，按自愈规则用同一个令牌重新 initialize，一秒内就回来了，断开等于没断。所以断开 = 删掉该 IP 的所有会话 + 10 分钟内拒绝该 IP：

- 检查顺序变为：网络 → 锁定 → **鉴权** → 断开拒绝 → 方法……。鉴权在前，所以错误令牌的探测仍按 401 计数、照常锁定。
- 返回 `403`，带 `Retry-After: <秒>`，响应体是 `{"error":"forbidden: disconnected by the desktop user, retry later"}`，前 200 字符**不含** "session"，手机会停下来，不会循环重连。
- 要永久拒绝某台手机，请轮换令牌（界面提示里写明了）。轮换和停止服务都会清空拒绝名单。
- 已知局限：按 IP 拒绝，同一 NAT 或同一 IP 后面的其他设备也会被拒 10 分钟；可以用“立即放行”解除。

## 测试

- Linux 全量：650/0/0/0（新增 9 个用例）。
- 新增用例：快照字段与排序；断开影响同 IP 的全部会话、不影响其他设备；被拒时旧会话和新的 initialize 都是 403 + Retry-After 且不含 session；错误令牌仍先返回 401；10 分钟到期自动解除；放行和 `dropAllSessions` 能解除拒绝；控制器回调；审计倒序与 200 条上限；字节格式和结果文案在三种语言里都有键；三语键齐全。

## 真机核对（建议）

1. 手机 `add --url` 接入后，“当前连接”出现一行，客户端名、IP 正确，调用次数随工具调用增加。
2. 点“断开”：该行消失；手机下一次调用报 403（不会自动重连），10 分钟内重新 `add` 也会被拒；“立即放行”之后可以重新连接。
3. 审计日志能看到刚才的调用，路径正确，没有令牌；点“清空”需要二次确认，清空后列表为空。
4. 依次把语言切到 English / 简体 / 繁體，两节文案都正确。
